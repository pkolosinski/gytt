# Architecture decision records

- Use an ADR for a durable architectural, module-boundary, or deployment
  decision, not for a transient implementation detail.
- Preserve the existing numbered filename and document structure.
- Record the decision and its consequences clearly, and reference the ADR from
  the relevant tech specification when the decision belongs to a change.
- Treat accepted ADRs as project history; do not rewrite them to describe a
  later implementation.
