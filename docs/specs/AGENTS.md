# Change specifications

- Keep one change under `docs/specs/<change>/`, using the existing product,
  tech, and plan documents.
- Read the product and tech documents before implementation; the plan is the
  execution checklist and must remain current.
- Keep plan tasks small, explicit, dependency-aware, and marked
  `pending`, `in progress`, or `done`.
- Put change-specific follow-ups in the same change directory rather than
  broadening unrelated docs.
